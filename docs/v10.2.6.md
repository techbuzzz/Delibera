## 🔴 F-01 — Async Streaming Council

### Goal
Enable real-time, round-by-round streaming via `IAsyncEnumerable<DebateRound>` so consumers
(ASP.NET Core SSE, WebSocket, Blazor, CLI) can react to each round as it completes.

### Motivation
Currently `ExecuteAsync()` blocks until all rounds + Chairman synthesis are done.
For debates with 4+ rounds and large models this can take minutes with no feedback.
The existing `OnRoundCompleted` event proves the pattern — this formalizes it.

### Proposed API

```csharp
// New method on ICouncilExecutor
IAsyncEnumerable<DebateRound> StreamDebateAsync(CancellationToken ct = default);

// Usage — CLI live output
await foreach (var round in executor.StreamDebateAsync(ct))
{
    Console.WriteLine($"[Round {round.Number}/{round.Total}] {round.Summary}");
}

// Usage — ASP.NET Core SSE
app.MapGet("/debate/stream", async (HttpContext ctx, ICouncilExecutor executor) =>
{
    ctx.Response.Headers.ContentType = "text/event-stream";
    await foreach (var round in executor.StreamDebateAsync(ctx.RequestAborted))
    {
        var json = JsonSerializer.Serialize(round);
        await ctx.Response.WriteAsync($"data: {json}\n\n");
        await ctx.Response.Body.FlushAsync();
    }
});
````


### Architecture Changes

- **`ICouncilExecutor`** — add `StreamDebateAsync(CancellationToken)` as default interface method
- **`CouncilExecutor`** — refactor internal round loop to `yield return` each `DebateRound`
- **`DebateRound`** — add `int Total`, `TimeSpan Duration`, `bool IsFinal` properties
- **`Delibera.ConsoleApp`** — add `--stream` demo flag


### Acceptance Criteria

- [x] `StreamDebateAsync` yields each round as it completes, including the final Chairman verdict round
- [x] Cancellation mid-stream aborts the current LLM call and stops iteration cleanly
- [x] `ExecuteAsync()` stays fully backward-compatible (internally calls `StreamDebateAsync` and collects)
- [x] Unit tests for streaming cancellation and round ordering
- [x] Demo: `dotnet run -- --stream`

## 🔴 F-02 — Pluggable Vote / Consensus Engine

### Goal

Allow the council to reach a decision via **structured voting** among participants,
as an alternative to the single Chairman-synthesis model.

### Motivation

Enterprise use cases (compliance, risk committees, architecture boards) often require
a traceable decision trail — not a single LLM synthesis, but a verifiable tally.

### Proposed API

```csharp
public interface IVotingStrategy
{
    Task<VotingResult> TallyAsync(
        IReadOnlyList<ParticipantBallot> ballots,
        CancellationToken ct = default);
}

public record ParticipantBallot(
    string MemberName,
    double Weight,
    IReadOnlyList<RankedOption> Rankings);

public record VotingResult(
    string WinningOption,
    double Score,
    IReadOnlyDictionary<string, double> Scores,
    string Method);

// Built-in strategies
public class MajorityVotingStrategy   : IVotingStrategy { }
public class BordaCountVotingStrategy : IVotingStrategy { }
public class WeightedVotingStrategy   : IVotingStrategy
{
    public Dictionary<string, double> MemberWeights { get; init; } = new();
}

// CouncilBuilder
.WithVotingChairman(new WeightedVotingStrategy
{
    MemberWeights = new() { ["SecurityExpert"] = 2.0, ["Architect"] = 1.5 }
})
```


### Architecture Changes

- **New**: `Delibera.Core/Voting/` — `IVotingStrategy`, built-in implementations, `VotingResult`, `ParticipantBallot`
- **`Chairman`** — add factory `Chairman.CreateVoting(IVotingStrategy)` alongside `CreateStandard`
- **`DebateResult`** — add optional `VotingResult? VotingTally`
- **`*_result.md`** — add **🗳️ Voting Tally** section when voting is used


### Acceptance Criteria

- [x] At least 3 voting strategies: Majority, BordaCount, Weighted
- [x] `VotingResult` included in `DebateResult` and rendered in Markdown output
- [x] Weights validated (must sum to > 0, non-negative)
- [x] Fallback to standard Chairman synthesis if no options can be ranked
- [x] Unit tests per strategy with known inputs/outputs
- [x] Demo: `dotnet run -- --voting`

## 🔴 F-03 — Debate Persistence \& Resume

### Goal

Allow a debate to be **checkpointed** after each round and **resumed** from any checkpoint,
surviving process restarts, infrastructure failures, or intentional pauses.

### Motivation

Long high-performance debates (4+ rounds, 3+ models, RAG enabled) can take 10–30 minutes.
A crash at round 3 means losing all prior work. Persistence also enables async/queued workflows.

### Proposed API

```csharp
public interface IDebateStore
{
    Task<string> SaveCheckpointAsync(DebateCheckpoint checkpoint, CancellationToken ct = default);
    Task<DebateCheckpoint?> LoadCheckpointAsync(string debateId, CancellationToken ct = default);
    Task<IReadOnlyList<DebateCheckpointMeta>> ListAsync(CancellationToken ct = default);
    Task DeleteAsync(string debateId, CancellationToken ct = default);
}

public record DebateCheckpoint(
    string DebateId,
    DateTimeOffset CreatedAt,
    int LastCompletedRound,
    IReadOnlyList<DebateRound> CompletedRounds,
    CouncilOptions Options,
    string OriginalQuestion);

// Implementations
public class FileDebateStore    : IDebateStore { } // atomic JSON write-then-rename
public class InMemoryDebateStore : IDebateStore { } // testing / ephemeral

// CouncilBuilder
.WithPersistence(new FileDebateStore("./checkpoints"))
.ResumeFrom(debateId: "debate-2026-07-06-abc123")
```


### `appsettings.json`

```json
{
  "Delibera": {
    "Persistence": {
      "Enabled": true,
      "Store": "File",
      "Directory": "./checkpoints",
      "RetentionDays": 30
    }
  }
}
```


### Architecture Changes

- **New**: `Delibera.Core/Persistence/` — `IDebateStore`, `DebateCheckpoint`, `DebateCheckpointMeta`, `FileDebateStore`, `InMemoryDebateStore`
- **`CouncilExecutor`** — call `SaveCheckpointAsync` after each round; on init check for existing checkpoint and skip completed rounds
- **`DebateResult`** — add `string DebateId` (auto-generated ULID if not provided)


### Acceptance Criteria

- [x] `FileDebateStore` saves/loads JSON atomically (write-then-rename)
- [x] `ResumeFrom` correctly skips completed rounds
- [x] Cancellation mid-round saves a checkpoint for the last completed round
- [x] Integration test: debate to round 2 → simulate crash → resume → verify final result consistency
- [x] Demo: `dotnet run -- --persistence`

## 🟡 F-08 — OpenTelemetry Observability

### Goal

Emit **structured traces and metrics** so production deployments can be monitored
in Jaeger, Zipkin, Prometheus, Grafana, Azure Monitor, etc.

### Activity Hierarchy

```
delibera.council.execute
├── delibera.council.round        (per round)
│   ├── delibera.member.respond   (per participant)
│   ├── delibera.rag.query        (if RAG)
│   ├── delibera.compression      (if compression)
│   └── delibera.operator.execute (if Operator)
└── delibera.chairman.synthesize
```


### Key Metrics

| Metric | Type | Tags |
| :-- | :-- | :-- |
| `delibera.debate.duration` | Histogram (ms) | — |
| `delibera.round.duration` | Histogram (ms) | `round_number` |
| `delibera.tokens.total` | Counter | `member_name`, `direction` |
| `delibera.compression.ratio` | Gauge | — |

### DI Registration

```csharp
services.AddDelibera(o => {
    o.Telemetry.Enabled = true;
    o.Telemetry.ActivitySourceName = "Delibera.Council";
});

// Standard .NET OpenTelemetry (user's responsibility)
services.AddOpenTelemetry()
    .WithTracing(b => b.AddSource("Delibera.Council").AddJaegerExporter())
    .WithMetrics(b => b.AddMeter("Delibera.Metrics").AddPrometheusExporter());
```


### Architecture Changes

- **New**: `Delibera.Core/Telemetry/` — `DeliberaActivitySource`, `DeliberaMeter`, `TelemetryOptions`
- All instruments are `static readonly` — zero overhead when no listener attached
- No new NuGet deps in `Delibera.Core` (uses in-box `System.Diagnostics.Activity`)


### Acceptance Criteria

- [x] All major operations emit `Activity` spans with relevant tags
- [x] Zero allocations when no listener is attached
- [x] README section: Jaeger + Prometheus setup
- [x] Demo: `dotnet run -- --telemetry`

## 🟡 F-09 — Dynamic Strategy Switching

### Goal

Allow the Chairman to **switch debate strategy mid-flight** when the current strategy is not converging
(stalemate, circular arguments, low response diversity).

### Proposed API

```csharp
public interface IStrategySelector
{
    ValueTask<IDebateStrategy?> SelectNextAsync(
        DebateProgress progress,
        CancellationToken ct = default);
    // Returns null to keep current strategy
}

public record DebateProgress(
    int CurrentRound,
    int MaxRounds,
    IReadOnlyList<DebateRound> CompletedRounds,
    double ResponseDiversityScore,  // cosine similarity across participant responses
    bool IsStalemate);

// Built-in selectors
public class AdaptiveStrategySelector : IStrategySelector
{
    public IDebateStrategy Initial { get; init; }
    public IDebateStrategy OnStalemate { get; init; }
    public int StagnationThreshold { get; init; } = 2;
}

// CouncilBuilder
.WithAdaptiveStrategy(new AdaptiveStrategySelector
{
    Initial = new StandardDebate(),
    OnStalemate = new CritiqueDebate(),
    StagnationThreshold = 2
})
```


### Architecture Changes

- **New**: `Delibera.Core/Debate/IStrategySelector.cs`, `AdaptiveStrategySelector`, `DebateProgress`
- **`CouncilExecutor`** — after each round call `IStrategySelector.SelectNextAsync(progress)` and swap strategy if non-null
- **`ResponseDiversityScore`** — computed via existing `IEmbeddingProvider` (cosine similarity); falls back to 0 if unavailable
- **`DebateRound`** — add `IDebateStrategy StrategyUsed` for audit trail


### Acceptance Criteria

- [x] Strategy switch logged in `ExecutionLog` and rendered in Markdown output
- [x] Single-strategy usage unchanged (no `IStrategySelector` = existing behavior)
- [x] Unit tests: stalemate detection triggers switch, diverse responses keep strategy
- [x] Demo: `dotnet run -- --adaptive-strategy`
